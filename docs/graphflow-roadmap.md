# GraphFlow 整合与续作

长期目标：星愿助手和 `starwish` MCP 是唯一入口。用户无需单独安装或配置
GraphFlow，便能完成其代码定位、变更验证、宏与项目工作流。允许随星愿分发
固定版本的 GraphFlow 引擎；不要求为替代入口而重写上游引擎。

## 阶段清单

| 阶段 | 状态 | 验收 |
| --- | --- | --- |
| 1. 只读适配 | 已实现首版 | 星图顶栏可打开 GraphFlow；本机 API 与 MCP 共用适配层；关键词及文件符号可精确返回行号 |
| 2. 增量图谱 | 已实现首版 | 内容校验刷新新增、修改、删除；同进程复用 AST；按行切片与结构化调用、导入位置。后续补输出 token 预算和大型仓库基准 |
| 3. 受控编辑与测试 | 已实现首版及依赖匹配 | 跨进程审批、哈希重检、回滚、Git 路径及静态导入依赖匹配、分页日志已实测 |
| 4. 宏与项目上下文 | 已实现工作流、台账及只读宏迁移 | 计划持久化、积压、回填、跨会话召回及 `context-bundle` 已实测；其他宏类型与动作待验收 |
| 5. 宿主接入与发布 | Codex 配置层和 SessionStart Hook 首版 | 隔离 Codex 已验证旧 MCP 停用、Hook 信任及触发；实际桌面迁移、安装产物待做 |

固定使用上游 3.9.2 的 `executeSurgicalRead` 和 `computeBlastRadius`。每个星愿
进程在私有临时目录复用一个工作区快照，正常退出时清理。每次查询重新枚举
允许的 Git 文件并校验内容哈希，快照只写入新增或修改的文件，删除项同时移除
对应 AST 缓存。不会向原仓库写缓存。跨进程不共享缓存，热查询仍需读取允许的
源码验证内容；并非文件监听或跨进程增量数据库。影响分析是静态启发式，结果
可用于定位证据，不保证动态分派、生成代码或被排除文件的调用关系。
明确给出文件路径的切片、影响分析、关系查询和单文件索引，会优先在同一容量预算内
纳入对应的受跟踪文件；未跟踪、排除目录和超限文件仍不允许。回到关键词或全局索引时
恢复原覆盖范围，可能补解析刚换出的文件。影响结果的 `index.partial` 仍需检查：
读到目标源码不代表找齐了调用方。
未直接接入上游的编辑、执行、宏、自动安装或 Hook。现有
`graphflow_context/plan/index` 这组旧入口，以及上游当前的
`gf_read/edit/exec/macro` 分别验收，不假定同名兼容。

旧入口 `graphflow_diagnose` 已接入 MCP 和星愿助手，本机面板也可请求
`GET /api/graphflow/diagnose`。返回授权状态、引擎、当前进程索引与任务积压汇总；
不主动刷新索引，不初始化台账，不导出源码、图谱节点或任务证据。兼容接受
`nodeLimit`、`edgeLimit`，但不导出图谱详情；不接受自定义 `configPath` 或越界根目录。

为星愿进程显式设置 `STARWISH_GRAPHFLOW_LEGACY_JOURNAL=1` 后，同一诊断会额外返回
`legacy_journal`。只读当前授权 Git 根的 `.graphflow/session-journal.jsonl`，
最大 1 MiB，拒绝链接、硬链接和灵魂包路径。统计旧版 `pending-episode` 的数量、
解析错误、年龄未知项及超过 30 天的项；这是旧文件现状，不代表星愿台账积压。
不会返回会话编号、正文、状态原值或路径，也不会导入、删除或重写旧日志。

`graphflow_artifact(mode="export")` 和网页「索引清单」可生成 `gzip+base64` 的
`starwish-index-manifest-v1`，包含允许的受跟踪文件路径和 SHA-256，不含源码。
用 `mode="import"` 与 `artifact` 传回时，需与本机当前源码清单完全一致；只从本机
源码预热当前进程，既不接受外部 AST，也不读取或写入调用方指定路径。压缩清单
并非旧版 GraphFlow 图谱格式，不能直接复用对方的解析缓存或跳过解析。路径和哈希
仍可能暴露项目结构，仅在合适范围内共享。

代码关系图可通过星愿助手、MCP `graphflow_graph(target="app/server.py")`，
或 GraphFlow 面板「代码关系」查看。空目标是有上限的概览，文件目标是一跳邻域。
返回文件、符号及行号，以及 `defines`、`imports`、`calls`、`doc-links-code`
和 `co-edit`。文档仅返回受跟踪的 Markdown 文件路径；共改来自最近最多 120
条非合并提交，过滤超大提交，并仅显示当前授权快照内的文件。共改是历史相关，
不是依赖；查询失败时查看 `history.status`，仅静态图谱仍可使用。
边的 `source`、`target` 是本次 `nodes` 数组的零基下标。只处理授权 Git 快照，
不返回引擎签名、源码片段、文档摘要或聊天。服务不接受写入路径；
网页可手动下载当前筛选视图的离线 HTML，不向服务器提交导出请求。
按 `nodeLimit`、`edgeLimit` 限制响应（最大 100 个节点、160 条边），
检查 `truncated`、`index.partial` 和 `history.more` 判断是否只是部分结果。
文件和符号名仍属项目数据。

`graphflow_skill_insights` 从当前项目最近 200 条已完成的任务回填中，按工作流统计
有代码引用或通过测试证据的任务。若任务有操作者关联的测试，以最近一条为准，
不重复计数，也不让更早的通过覆盖后续失败。每组最多给两个可复核任务 ID，不返回聊天、总结、
源码或日志；它不创建台账或自动修改技能。`graphflow_skill_guide` 返回当前工具与
审批指南。两者均不导入旧 GraphFlow 学习记录，历史回填不证明当前仍然有效。

启用星愿任务台账后，旧入口 `graphflow_run(task=...)` 返回执行说明及待回填的
`episodeId`，不执行代码、编辑或测试。`graphflow_report_outcome` 可用该编号回填
是否完成及最多四条单行经验；可附 `revision` 做版本校验及 `references` 供复核。
未完成映射为阻塞，完成结果可由项目上下文召回。不导入旧编号、不自动回填，
也不写通用记忆；自定义配置路径不受支持。

| 上游入口（3.9.2） | 星愿当前对应能力 | 还未覆盖的行为 |
| --- | --- | --- |
| `gf_read` | 星愿 MCP 原名接入，返回纯文本；关键词、多目标、结构视图、行范围、显式会话去重、星愿任务续读、可选旧编号定位及 `@brief` 交接；独立工具可迁移选中的旧待办 | 不导入旧日志正文或批量迁移，不自动发现其他仓库 |
| `gf_edit` | 原名预览入口：行范围、唯一完整原文、符号、跨文件批量及静态重命名；人工审批和回滚 | 超限及动态引用不保证覆盖；不接入上游自动写入和旧响应格式 |
| `gf_exec` | 原名只读入口：状态、项目诊断及仓库内宿主文件线索、导入依赖测试定位、星愿及已授权的 3.9.2 旧日志读取；测试仍走面板审批 | 不扫描用户目录判断全局注册；不接入上游命令执行 |
| `gf_macro` | 只读宏、星愿台账、历史共改、新旧轨迹代码包及本机人工固定；编辑宏转审批；命令宏可映射到预设测试 | 不执行旧脚本或自动运行管线；不自动保存宏定义、不全面兼容旧响应格式 |

## 当前接入

使用 Node.js 18+、Git，以及 GraphFlow 3.9.2 官方发行包。Windows PowerShell：

```powershell
python tools/graphflow_engine.py install
python tools/graphflow_engine.py check
$env:STARWISH_GRAPHFLOW_WORKSPACE = (Get-Location).Path
uv run --no-project --with-requirements requirements.txt python run.py --host 127.0.0.1 --port 17860 --no-browser
```

从星愿源码仓库根目录执行。安装命令仅安装 npm 发行包到星愿专用目录，禁用
安装脚本，不注册客户端或独立 MCP；先在临时目录实跑切片和图谱再发布。
新安装用 `npm ci` 和仓库中的锁文件固定传递依赖，校验 npm 官方包地址和
SHA-512 完整性字段。安装不更新锁文件；换引擎版本时需同步更新版本与锁文件后重新验收。
已存在的目录只自检、不覆盖。可用 `--prefix` 指定独立目录，
`--offline` 仅适用于 npm 缓存已完整的情况。

Windows 发布构建可用 `python tools/build_windows.py --with-graphflow` 随包放入固定
引擎。构建机需 Windows x64 的 Node.js/npm、Git 和原有启动器编译依赖；
加 `--graphflow-offline` 时只用已有 npm 缓存。引擎安装后先跑切片和图谱自检，
再保留各实际安装依赖的许可/归属文件及 `THIRD-PARTY.json` 清单。发布包不含 Node.js、
Git 或 npm 缓存；运行时仍需本机 Node.js 和 Git，但不需 npm 或单独注册 GraphFlow。
GitHub 源码不包含运行模型。Windows 构建可用
`--models-dir <绝对模型目录>`（也可设置 `STARWISH_MODELS_DIR`），该目录需包含
`embed/small/model.onnx` 和 `embed/small/tokenizer.json`，如已安装的可信星愿
运行目录中的 `models`。构建只复制这两个必需文件；模型来源不得位于将被重建
的输出目录内。仅从源码运行 GraphFlow 项目工具不需要向量模型。
声纹模型可通过 `--voice-models-dir <绝对目录>` 从本机可信模型目录复制（常用
`models/voice`），只取两个约定的 ONNX 文件，不下载或读取用户语音设置。
输入目录也不能在构建输出内；此选项与 `--no-voice-models` 互斥。
如已有可信的 Windows x64 嵌入式 Python 运行时，还可显式传
`--runtime-dir <运行时目录>`，复用 Python 3.12.10 及其 `site-packages`，
不下载 Python 或 wheels。构建前验证依赖可导入，重新生成相对路径配置，
不会复制原应用目录或灵魂包；必须使用已验证的运行时，不能把不可信目录当输入。
单文件构建同时输出同名 JSON 校验清单，包括版本号、大小、EXE SHA-256、
ZIP 载荷 SHA-256 和缓存标签。正式发布可在干净检出中用
`--release-commit <完整提交哈希>`；构建前后均核对当前提交及未提交文件。
普通构建的 `source_commit` 为 null，不能据此追溯到某个 Git 提交。
优先使用显式 `STARWISH_GRAPHFLOW_PREFIX`，否则优先随包引擎，再找用户目录。
检查暂存目录可运行 `python tools/graphflow_engine.py bundle-windows --prefix <绝对应用目录>`；
该命令只准备引擎，不生成 Windows 启动器。

从 Windows 目录版生成 Codex 配置时，可运行包内 `runtime\python.exe` 和
`tools\graphflow_codex.py preview`。检测到嵌入式运行时后，生成的 STDIO 命令直接
使用包内 Python，不依赖 `uv` 安装依赖；移动应用目录后需重新生成绝对路径配置。
这条接入方式不改变桌面 Hook 对 PATH 和客户端信任的要求。
使用支持 `--mcp` 的星愿 Windows 启动器时，可给 Codex 配置生成器显式传
`--launcher-exe <绝对 EXE 路径>`。配置直接启动该 EXE 并留出
`startup_timeout_sec = 90` 以容纳单文件首次解包；探针相应可加
`--startup-wait 105`。不改记忆目录授权或审批规则。
已有实例切换前，先确认原启动方式和原
`STARWISH_SOUL_DIR`，沿用原灵魂包，不要创建或覆盖生产数据。
自定义安装路径用
`STARWISH_GRAPHFLOW_PREFIX`。仅管理员在进程环境中指定可信 Git 仓库，工具和页面
不能改目录。不将本机代码路由反向代理给其他设备。只读快照只复制 Git 已跟踪的
允许类型文件的当前工作区内容，排除隐藏目录、灵魂包、链接、硬链接与 Windows
重解析文件。快照、编辑证据和测试审批校验共用读前文件身份检查，打不开或换了
身份的文件不读。不要授权包含已提交秘密或无权转交内容的仓库；路径规则不是
秘密扫描器，这也不是防同权限本机进程的沙箱。

其他 Agent 使用现有星愿 STDIO MCP，在其启动环境单独配置同样的工作区变量即可
调用 `graphflow_read`（关键词、路径、路径#符号或路径:起始行-结束行）和
`graphflow_impact`（路径#符号），无需注册第二个 MCP。网页查询不向模型发送代码。星愿聊天
助手默认不提供此工具；明确同意把查询结果发给所选模型后，在星愿网页服务的启动
环境设 `STARWISH_GRAPHFLOW_ASSISTANT=1`。外部 Agent 是否转交其模型由该客户端决定。

内置助手按授权的 Git 根保存项目对话；关闭授权后切回普通记忆对话，换项目后只加载
新项目的历史。助手的「清空」只清空当前范围。旧 `soul/agent/chat.json` 若有项目工具
标记或来源不可核验的压缩摘要，原样留在磁盘但不自动显示或发送给模型；未压缩、无项目
工具标记的旧普通历史仍可读取。设置中的数据重置会先做快照，再清除这些历史。

使用 `gf_read` 可一次传最多 12 个 `targets`，或用 `q` 查询；显式目标优先。
`topK` 限制关键词候选（默认 6，范围 1 到 12），`skeleton` 请求结构视图。
所有目标先校验，再共用一次快照刷新；一个目标不合法或不在跟踪范围内，整批拒绝。
`rootDir` 只能等于已配置的 Git 根。启用 `dedup: true` 时，客户端须为每个会话生成独立随机的
`sessionId`（16 到 128 位字母、数字、下划线或连字符，同会话复用）。相同请求在索引快照和结果都未变化时
返回简短提示；关闭 `dedup` 可重新取正文。进程内最多保留 256 条摘要，15 分钟不访问即过期，
不保存源码、不写入记忆。开启项目任务台账后，可将 `graphflow_run` 返回的
`episodeId` 作为 `topicId`（或 `resumeFromTurnId`）交给 `gf_read`。
未传 `targets` 或 `q` 时，使用保存的代码目标或关键词；显式参数优先。
每次都读取当前授权索引，不返回任务回填、旧源码或其他客户端的对话日志。
未知 ID 或其他项目的任务明确返回未找到，不创建台账。话题作用域是已授权项目，
与会话内去重的作用域不同。
旧话题续读需要单独设置 `STARWISH_GRAPHFLOW_LEGACY_TOPIC_RESUME=1`，不随积压诊断
开启。星愿任务优先；否则只在本工作区的受限旧日志中对 `topicId`、`turnId`、
`episodeId`（或旧待回填记录的 `id`）精确匹配，不查正文子串。不从旧日志推断
源码位置，例如用 `gf_read({"resumeFromTurnId":"legacy-turn-11","targets":["app/server.py:1-10"]})`
显式指定当前源码。返回匹配提示及当前源码，不读取旧日志的正文到对话、
不导入任务、不写旧日志或台账。

若确实要接手旧待办，需同时设置 `STARWISH_GRAPHFLOW_TASKS=1` 和
`STARWISH_GRAPHFLOW_LEGACY_TASK_IMPORT=1`。调用 `graphflow_legacy_task_import`
的 `list` 只列旧待办编号（每页 20 个，`after` 使用返回游标）。
用 `preview` 指定 `legacy_id` 和当前 `target="文件#符号"`，预览会核验唯一符号
及其行号；核对后以相同参数调用 `import`，附预览的 `confirm_sha256`。
原记录、目标源码或工作流变更须重新预览。拒绝重复或已识别回填的旧待办，
同一编号的同一计划重试只返回原星愿任务。只登记新的待办身份、源码目标和迁移
来源，不复制旧聊天、摘要、测试证据，不执行工作流或改写旧日志。
输出仍受星愿原有长度限制，已有 `graphflow_read` 的单目标和 JSON 格式保持不变。

`gf_read({targets: ["@brief"]})`（或空参数）返回项目交接简报。固定引擎仅在隔离快照
中计算当前架构枢纽和文档关联；星愿另列当前授权项目最多五条任务状态和显式回填、
一条最近 24 小时内已结束的授权测试状态。任务可用 ID 续读，历史回填不等于本轮验证。
简报可与代码目标同批读取；不读取上游活动文件、聊天记录、测试命令或日志，不创建台账。

网页「编辑预览」和 `graphflow_edit_preview` 接受相对路径、起止行（含）、
原始行文本和替换文本，替换文本留空代表删除。只允许已跟踪且没有合并冲突的
常规 UTF-8 文件。预览返回 unified diff 和原文件/候选文件的 SHA-256；
`graphflow_edit_check` 验证原文件全量哈希，删除、移出版本控制、修改任一行均使
预览失效。默认凭据只保留在创建它的进程中，最长十分钟，不能用于授权写入。

星愿助手和 MCP 的 `gf_edit` 支持 `preview_only: true`：用同一套工作区、原文和
差异检查返回 diff 及前后哈希，但不创建审批项或进程内凭据。适用于单处、批量
替换和静态重命名；已有默认行为不变。有意提交审批时需另行生成正常预览。

旧客户端也可调用 `gf_edit` 生成同一种预览。必填 `oldCode`（完整原文行）与
`newCode`（空字符串表示删除）；指定 `startLine/endLine`、`symbol`，或只用唯一
原文定位。重名符号需加类名或改用行范围。`edits` 可合并最多 4 个文件、8 处、
总计最多 200 个原始行的非重叠替换；每项可传 `file` 或继承顶层路径，坐标均基于
原文件。`rootDir` 只能是已授权 Git 根，MCP 不直接写文件。

`gf_edit(file=..., symbol=..., renameTo=...)` 可预览静态重命名，不与替换参数混用。
固定引擎只在一次性副本中生成候选，星愿核对变更文件清单和原文哈希，再交给同一
审批队列。最多 4 个文件；若超过上限、快照达到容量限制、引擎拒绝或原文已变化，
不会提交部分预览。分析仅覆盖快照中允许的已跟踪文件；动态引用、忽略文件和预览后
新增的调用点仍需人工核对。审批只保护预览所列文件，完成后应跑相关测试。

### 可选：本机写入审批

默认关闭。要启用，网页服务和提交预览的 MCP 都需要设
`STARWISH_GRAPHFLOW_EDIT_QUEUE=1`，并沿用相同的工作区、灵魂包路径和本机应用数据目录。
**仅网页服务**另设 `STARWISH_GRAPHFLOW_OPERATOR_KEY`，使用至少 24 字符的随机 ASCII
密钥；不要将它写进 MCP 配置、助手对话或项目文件。网页的「本机编辑审批」中手动
输入密钥、选中记录核对 diff，再确认写入。MCP 和助手没有写入或回滚工具。

共享队列位于本机应用数据的 `StarWish/project-edits`，在工作区和灵魂包之外，
包含候选内容与恢复所需原文。过期预览、已回滚记录、超过回滚窗口的记录会在
后续访问队列时清理源码内容；审计只记编号、路径、状态和时间，最多 30 天。
回滚窗口为 24 小时。若写入中断，面板可在 30 秒后按现有文件哈希恢复记录状态，
不会在恢复检查时改文件。写入前会重新核对跟踪状态和整文件哈希，随后同目录
原子替换；仍不要与外部编辑器或程序同时写同一个文件，此设计不是跨进程文件
比较交换，也不是针对同一操作系统账号内不可信程序的隔离层。

跨文件审批使用一张审批单，确认哈希覆盖排序后的文件路径和各文件哈希，操作前
逐个校验。每个文件单独原子替换，整组不是原子事务。中途失败时保留进行中状态，
并阻止星愿其他审批写入这些文件。30 秒后在面板核对；若已部分写入，可单独确认
回滚。只恢复仍与审批前或审批后哈希相符的整组文件，任何外部改动都会阻止整组
恢复；核对本身不写文件。

### 可选：受控测试

给星愿网页服务设置 `STARWISH_GRAPHFLOW_TEST_PROFILES`（JSON 对象）及同一个
操作者密钥。无需开启写入审批。例：将程序路径换为已装项目依赖的本机解释器。

```json
{
  "graphflow-check": {
    "argv": ["C:/path/to/python.exe", "-m", "unittest", "discover", "-s", "tests", "-p", "graphflow*_test.py"],
    "paths": ["app/graphflow*", "tests/graphflow*"],
    "timeout": 30
  }
}
```

匹配范围为 Git 已跟踪的允许类型源码，包含已暂存和未暂存改动；`paths` 为空时
总可选。没有直接命中时，在受限快照用固定引擎的静态导入分析定位测试，再匹配
预设方案；引擎不可用则只显示直接匹配。改动文件优先进入同一有界快照；快照部分
覆盖或改动中有缺失文件（例如已删除）时，静态建议标记为不完整，不代表没有其他测试。
运行前复核审批哈希：绑定 Git HEAD（未提交的新仓库也可用）、测试配置、间接匹配，
以及 Git 识别的允许类型改动文件的路径、暂存条目和当前字节 SHA-256。提交、同一路径
内容或暂存版本变化都需重新审批；此前版本生成的审批需刷新。
不指纹化未跟踪文件、忽略项或其他依赖，也不锁定快照；运行的是当前工作区，
复核后仍可能发生并发修改。超预算或遇冲突、链接等非常规改动时拒绝生成审批。
测试工具不接受临时命令或参数，不经 shell。只配置你信任的程序和
项目测试；子进程不继承审批密钥等非白名单变量，但**不是沙箱**，不要配置会访问
外部服务、泄露凭据或修改重要数据的命令。超时 1–120 秒，同工作区一次运行一个；
子进程清理尽力而为，测试程序应自行管理派生进程。最多保存 128 KiB 合并输出，
每页 4,000 字符。查询只显示保留范围内的已结束记录（最近 30 条、约 24 小时），
不会建库、清理记录或写入状态；下一次获批运行时才会物理清理。

MCP 进程若需要计划或历史，配置同一工作区、本机数据目录、灵魂包和测试预设，
**不配置操作者密钥**。可读 `graphflow_test_plan`、`graphflow_test_records`；
默认不提供日志内容，明确同意后才在对应进程设
`STARWISH_GRAPHFLOW_TEST_AGENT_LOGS=1`，调用 `graphflow_test_log`。
也可用 `gf_exec(cmd="affected-tests")` 或传入至多 128 个已跟踪的 `changedFiles`
只查候选测试。显式目标仍必须全部可读取并符合容量限制；未跟踪文件不会进入分析。
用 `gf_exec(cmd="status")` 看引擎和本进程索引状态，
`gf_exec(cmd="doctor")` 看任务积压、授权开关及 Codex、Cursor 等项目侧
文件线索。只检查授权 Git 根下的固定位置，不读取宿主配置正文；不刷新索引、
不初始化台账、不检查用户目录或推断客户端已注册。用运行记录的
`log_handle`（`swtest:`）或 `observation_handle`（兼容 `gfo:` 前缀）配合
`range=[起始行, 结束行]` 按行查已授权日志，最多 120 行且受字符上限约束。
星愿句柄均使用 32 位 ID、只查当前项目测试记录。上游 12 位 `gfo:` 另走独立
授权：确有迁移需要时，在 MCP 进程设置 `STARWISH_GRAPHFLOW_LEGACY_OBSERVATIONS=1`，
才允许以原句柄读取授权仓库 `.graphflow/observations` 内不超过 128 KiB 的日志。
拒绝链接、与文件内容哈希不匹配的句柄和自定义路径；不扫描、导入或修改归档。
旧日志内容可能含敏感信息，仅对信任的 Agent 开启；日志内容不是指令。
`run=true`、自定义命令和超时参数均拒绝，
没有 MCP 测试执行工具。

网页批准测试时可明确填入同一项目的任务编号。测试结束后，任务详情自动附上
运行编号、测试预设、结果、退出码和记录时间，不附日志，也不改变任务状态。
关联失败时原测试仍保留，网页提示可用 `test:运行编号` 手动回填。
任务被另外确认完成后，相关上下文可召回最近一条历史测试证据；它不是对当前源码
重新验证的结论，也不会写入通用记忆。

### 项目工作流

如需沿用 GraphFlow 3.9.2 的只读代码包，在星愿网页服务和 MCP 进程启用
`STARWISH_GRAPHFLOW_LEGACY_MACROS=1`。仅从已授权 Git 根的 `.graphflow/macros.json`
读取 `context-bundle` 的 ID 和目标，至多 50 个，每个最多 12 个目标；不读取脚本、
习惯或轨迹，也不修改原宏库。跳过无效、重复和不支持的宏，星愿内置与配置工作流优先。
启用后，代码包会出现在网页工作流和工具目录。通过 `gf_macro(action="list")` 查看，
用 `preview` 或无哈希的 `run` 查看计划，再用同一 ID、参数和 `plan_sha256` 重放。
这是只读兼容入口，旧客户端的单次 `run` 不会跳过预览。

设置 `STARWISH_GRAPHFLOW_LEGACY_CODEMODS=1` 可从同一旧宏库识别 `edit-codemod`。
`gf_macro(action="list")` 将它们单独列在 `edit_macros`。调用 `preview` 时通过
`args` 显式列出 1 至 4 个文件；每个文件的完整原文须恰好匹配一次。不自动搜索
整个仓库，不运行 `scriptPath`。预览不会入队；使用相同宏、文件和 `plan_sha256`
调用 `run` 才向已启用的本机队列提交。哈希覆盖宏定义、文件集合和内容；源码写入
与回滚仍须本机操作员确认。可从网页现有审批面板查看完整差异。

管理员可设置 `STARWISH_GRAPHFLOW_LEGACY_COMMAND_MAP`（例如
`{"verify":["smoke","unit"]}`），将旧 `command-template` 或 `command-pipeline`
的 ID 按步骤映射到星愿已配置的测试方案。映射只使用方案名称，不解释旧命令、
脚本或占位符。`list` 在 `test_macros` 中列出映射；`preview` 查看当前可用方案，
带原计划哈希的 `run` 只返回待人工审批的顺序。宏定义、映射或有效测试计划变化时
必须重新预览。实际运行仍由本机面板逐项审批，不执行旧命令或自动串联步骤。

`gf_macro(action="mine-git")` 和网页工作流「历史共改线索」分析当前 Git `HEAD`
可达的最近 120 条非合并提交，跳过一次改动超过 20 个文件的提交。只返回当前仍
受版本控制的允许类型文件，至少两次同改才形成候选，最多返回 12 对。共改次数
和置信分只反映历史相关性，不证明依赖，也不读取提交正文或写入宏库。

单独设置 `STARWISH_GRAPHFLOW_LEGACY_TRAJECTORIES=1` 可用 `gf_macro(action="mine")`
从项目的 `.graphflow/trajectories.jsonl` 推导只读代码包。文件至多 1 MiB，查看末尾
500 条；仅统计成功的源码读取（重复批量读取，或同一会话内不重叠的相邻单项读取）。
每包最多 6 个当前受跟踪的目标，至少出现两次；最多返回 12 包。输出不含会话标识、
时间和命令，不修改轨迹文件、宏库或源码。候选可在目录预览并凭计划哈希重放；
候选不再满足条件时不可重放；不生成脚本。

星愿可独立积累新轨迹，不依赖 GraphFlow 客户端。在处理读取的助手或 MCP 进程
显式设置 `STARWISH_GRAPHFLOW_READ_TRAJECTORIES=1`，在挖掘或重放进程使用同一
授权 Git 根和本机数据目录，并开启相同开关。只采集带有效 `sessionId` 的
`gf_read`，每次最多六个明确、全部得到引擎确认的位置；不采集关键词、任务
续读、简报、失败或去重命中。当前符号匹配只采集引擎按原目标精确确认的键。
最近 500 次保存在工作区与灵魂包之外的本机数据库，内容仅为目标位置和会话摘要，
不含原会话 ID 或源码。关闭开关会停止采集和读取，不删除本机文件。
`gf_macro(action="mine")` 合并已启用的来源，候选进入现有工作流目录。
重放仍需预览哈希，没有会话 ID，不反向采集，也不写宏定义或执行测试。

想长期保留某个轨迹代码包，可在网页「项目工作流」选中候选，预览后输入本机
操作者密钥并点「固定此代码包」。本机库只保存该包的目标位置，每个工作区最多
24 个，不随轨迹滚动淘汰。即使关闭轨迹来源，也可从星愿助手、MCP 或面板预览和
重放；重放只读当前仍获授权的 Git 文件。取消固定也需密钥；如果近期轨迹仍满足
条件，该包会回到候选。星愿助手和 MCP 不直接管理固定状态，不改旧宏库或仓库。

启用星愿项目台账后，`gf_macro(action="task-list")` 返回最近 20 条任务（含已完成）。
`task-run` 使用星愿任务 ID；不传 `plan_sha256` 时查看保存的计划和最新回填，传入该
哈希后仅重放保存的只读步骤。不能替换参数、自动运行测试或更新任务；计划配置变化后
须重新生成计划并登记新任务。任务创建和结果回填仍用 `graphflow_task_create` 与
`graphflow_task_report`，不导入或执行旧 `.graphflow/tasks.json` 里的脚本。

配置可信工作区后，网页「项目工作流」、助手和星愿 MCP 共用工作流目录。
内置 `symbol-review`（传入 `target=文件#符号`，读取代码、分析影响、建议测试）
与 `change-review`（查看 Git 改动并建议测试）。分别调用
`graphflow_workflow_catalog`、`graphflow_workflow_preview`、
`graphflow_workflow_replay`。预览不执行步骤，重放要提供相同参数和计划哈希；
哈希锁定工作区、步骤和输入，不锁定源码版本。重放时读取当前文件，
任一步失败就停止，不写文件、不启动测试；测试建议需在本机面板单独审批。

可通过本机启动环境 `STARWISH_GRAPHFLOW_WORKFLOWS` 添加固定模板（JSON），例如：

```json
{
  "review-by-query": {
    "title": "按关键词查看代码结构",
    "steps": [
      {"op": "read", "query": "$query", "skeleton": true},
      {"op": "test_plan"}
    ]
  }
}
```

每个模板最多六步，仅接受 `read`、`impact`、`changes`、`test_plan`。
`$target` 和 `$query` 是完整字段占位符，不做 shell 插值。上游 3.9.2
`gf_macro` 的旧模板、管道、批量编辑和挖掘仅按前述边界兼容，不宣称完整兼容。

### 项目任务台账与上下文

在网页服务和需要共享台账的星愿 MCP 进程设置 `STARWISH_GRAPHFLOW_TASKS=1`，
使用同一工作区、灵魂包路径和本机应用数据目录。默认关闭，不需写入审批密钥；
只向可信 Agent 启用，因为它们可以写台账元数据，但不能借此编辑源码、运行
测试或写入通用记忆。网页可把工作流预览存入台账，查看积压、任务详情并回填。
MCP 提供 `graphflow_task_create`、`graphflow_task_backlog`、
`graphflow_task_detail`、`graphflow_task_report`。

创建时重试应复用同一个 `request_id`；回填必须带当前 `revision`。台账状态是
待处理、阻塞或调用方报告完成，不会自行运行工作流或判定任务完成。回填可附
`code:文件:起始行-结束行` 或 `test:运行编号`，分别验证现有代码范围和已结束的
测试记录。台账只保存计划、简短回填、文件位置与哈希、测试编号与退出结果；
不会自动保存源码或日志，也不保证历史测试与当前文件一致。数据保存在本机
`StarWish/project-edits` 的独立 SQLite 文件中，不进灵魂包。

`graphflow_context(query, budget_tokens, rootDir)` 组合当前代码锚点和相关历史
回填。可选 `rootDir` 只能核对已授权工作区，不能切换项目。返回
`summary`、`anchors`、`outcomes`、`tokenBudget`；预算是估算值。
需要原文时用锚点的 `read_target` 调 `graphflow_read`，需要完整回填则按任务编号
取详情。历史回填只检索最近 200 个已完成任务，不等于重新验证。
随上下文返回的历史代码证据用 `source_state` 标明：`matching_bytes` 表示当前
可读受跟踪文件的完整字节与回填时一致，`changed` 表示哈希不同，
`unavailable` 表示无法在当前授权范围核验。测试证据（手工引用和最近一次
关联测试）另有 `plan_state`：`matching_plan` 表示保留记录中的审批哈希和当前
可选计划一致；`changed_plan` 表示不一致；`unavailable` 表示记录过期、预设不可选
或无法重新计算。字段按需计算，不返回审批哈希、命令或测试日志，不改写台账或通用记忆。
即使代码字节或审批计划一致，历史结果也不等于当前验证，不会执行测试。
目前覆盖旧 `graphflow_context` 的查询入口，不支持其归档句柄或全部旧参数。

`graphflow_index(mode, filePath, rootDir)` 支持增量、单文件和全量索引。路径
只允许已授权项目中的受跟踪源码；`rootDir` 只能核对已配置的项目。全量仅清除并
重建当前星愿进程的临时快照和 AST，不触碰源仓库，也不清理独立 GraphFlow 的缓存。
进程不共享预热结果；每次读仍核对文件内容，不能依赖另一个进程先刷新。

`graphflow_plan(task, mode, rootDir, query, target, intent)` 返回上下文锚点、
待核对问题、`plan.steps` 和依赖 DAG。默认 `intent=review`，不假定要写入；
显式 `intent=change` 才会列出 diff、写入审批、测试审批、条件回滚和回填。
`mode=insight` 添加六顶思考帽和五问提示，答案仍要用证据验证。规划不执行、
不写文件、不自动持久化。返回的 `read_only_workflow` 可原样传给重放，
或者加 `request_id` 存入任务台账；它只包含可以重放的只读子流程，不是
对完整变更 DAG 的授权。旧版的 workbench 主题树、代理分解合并和
调用方提供的 `configPath` 不在兼容范围内。

### Codex 客户端试迁移

从星愿源码仓库运行只读预览，`--soul` 指向实际正在使用的灵魂包：

```powershell
python tools/graphflow_codex.py preview --workspace (Get-Location).Path --soul 'D:/path/to/soul' --with-tasks --with-hook
```

只有在 `codex mcp list` 已确认存在同名旧服务时，才加
`--disable-server graphflow` 或 `--disable-server user-graphflow`。生成器只打印
TOML，不修改客户端配置，不携带审批密钥。不用别名选项时不读取客户端配置。
对于改名的入口，先用 `graphflow_codex_probe.py --config-only` 核对候选和实际用途，
再给 `preview` 或 `install` 加 `--project <绝对路径> --codex <Codex绝对路径>
--disable-alias code-index`；有多个已核实别名可分别传参。工具只读检查当前项目
生效配置，不启动服务；只生成显式选中且仍启用的候选停用项，拒绝星愿、无标记、
已停用及未注册的名称。名称或启动参数中的标记只是线索，不能替代对服务用途的核对。
如果已有同名星愿服务，
请先核对传输类型和环境变量，避免把本机 STDIO 与现有远程配置混在一起。

桌面优先使用已信任项目的 `.codex/config.toml`，不改全局配置。已有文件时先核对并
合并，不覆盖；回滚时只撤销这次添加的配置项。源码仓库在桌面项目目录内时，
`--workspace` 仍指向内层 Git 根；若同时启用 Hook，用 `--client-root` 指定
桌面打开的外层绝对路径。这个选项仅让 Hook 接受外层目录本身，不授权扫描外层
或其余子目录。放入项目层后，在桌面打开的目录运行 `codex mcp list --json`
核对星愿已启用；不在不相关的项目重复安装。

若项目还没有 `.codex/config.toml`，可从源码仓库用管理工具安装和撤销。安装
只创建项目文件，不覆盖已有配置，也不修改全局信任或审批密钥。保留安装返回的
`sha256`；撤销仅删除仍与该哈希相同的星愿管理文件，遇到手动修改则拒绝。

```powershell
python tools/graphflow_codex.py install --project 'D:/path/to/project' --workspace (Get-Location).Path --soul 'D:/path/to/soul' --with-tasks --with-hook
python tools/graphflow_codex.py uninstall --project 'D:/path/to/project' --workspace (Get-Location).Path --sha256 '<installation sha256>'
```

可用 `python tools/graphflow_codex_probe.py --help` 查看只读验收工具。它读取实际
项目配置，用指定的 Codex 程序开临时会话，拒绝独立 GraphFlow 仍启用的配置，
并验证测试灵魂包、代码锚点、源码范围和审批边界。使用预先写入测试标记的隔离
灵魂包；不启动模型轮次，也不打印记忆或源码。它不负责安装或变更配置。

可在 Codex 配置目录单独建 `starwish-project.config.toml`，用
`codex -p starwish-project mcp list` 检查，再用 `codex -p starwish-project`
开启会话。不用 `-p` 即回到原配置。本机安装的 0.164.0 不支持在
`codex app-server` 上传 `-p`；应用服务器验证使用隔离的已合并配置。

要让桌面 MCP 提交编辑预览到网页审批队列，生成新配置时传 `--with-edit-queue`。
已安装的项目只需在现有 `[mcp_servers.starwish.env]` 中手动添加
`STARWISH_GRAPHFLOW_EDIT_QUEUE = "1"`，不要重新覆盖配置，也不要把审批密钥写入
该段。网页服务需另行启用同一队列；两进程须使用相同 Git 根、灵魂包和本机状态目录
（Windows 为 `LOCALAPPDATA`）。审批密钥只配置在网页服务进程，至少 24 位。
GraphFlow 面板区分功能未启用与密钥未设置，不读取审批记录或显示密钥。

可选 `SessionStart` Hook 只对已授权工作区内的启动和恢复返回固定提示，
不读取聊天、源码或日志，不调用命令或写台账。Windows 需要 `python.exe`
在客户端 PATH 中。客户端必须通过 `/hooks` 审查信任；本项目不绕过信任。
参见 [Codex Hooks](https://learn.chatgpt.com/docs/hooks#sessionstart)。

真实项目可用 `--verify-hook` 验证启动注入（与 `--hooks-only`、`--project-only`
互斥）。在桌面输入框点「Review hooks」或从「设置 → Hooks」人工核对项目层的
`SessionStart`，确认命令只指向星愿 `tools/graphflow_codex.py session-hook` 后再信任。
探针不会写入信任；项目 Hook 不受信任或存在其他启用 Hook 时，不启动模型轮次。
已信任时使用临时只读会话、禁用 MCP 和网页搜索，并确认选择回环模拟模型后才发起
固定探测。只检查 Hook 完成事件和提示是否进入回环请求，不打印请求内容。
探针同时给出项目配置路径及其他启用 Hook 的事件计数，不输出其他 Hook 的命令。
项目命令、匹配范围或执行方式与星愿生成的配置不符时，即使已信任也不启动验证轮次。
若唯一阻碍是其他启用 Hook，可在 `--verify-hook` 后追加
`--isolate-other-hooks`。探针先只读获取其他 Hook 的内部标识，再用进程级覆盖
临时禁用它们；第二次列表核对所有目标确实关闭，且星愿 Hook 仍由 Codex 判定为
已信任，才发起本机模拟验证。不改用户或项目配置，也不写入信任。
若桌面确认后仍显示未信任，先用 `--hooks-only --explain-hook-trust` 查看
Codex 新进程实际加载的用户配置路径、配置档、该定义的信任记录是否匹配，以及
Windows 上是否存在仅大小写或分隔符不同的键。只输出诊断状态，不输出哈希、
其他配置或命令，也不开启会话。若记录缺失，在桌面以对应目录的会话重新检查，
或从该目录启动同一 Codex 后使用 `/hooks` 单独审查项目的 `SessionStart`。

现场只读预检可一次核对面板、客户端注册和 Hook：

```powershell
$codex = (Get-Command codex.exe).Source
python tools/graphflow_codex_probe.py --codex $codex --project 'D:/path/to/codex-project' --workspace (Get-Location).Path --panel-preflight http://127.0.0.1:17860
```

预检仅访问回环面板的状态接口，用一次性校验值核对规范化 Git 根目录，
不返回绝对路径；旧版本不支持校验时，不以目录同名代替。它不替代正式项目的
符号查询，也不会启动 MCP、运行模型或签收人工审批。`ready_for_operator_verification`
仅表示可开始网页和 Hook 的现场验收，不表示已迁移。

```powershell
$codex = (Get-Command codex.exe).Source
python tools/graphflow_codex_probe.py --codex $codex --project 'D:/path/to/project' --workspace (Get-Location).Path --verify-hook
```
